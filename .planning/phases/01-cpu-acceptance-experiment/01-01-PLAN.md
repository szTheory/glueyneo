## Artifacts this phase produces

All `files_modified` paths above are new execution artifacts; none is an existing implementation. Runtime consists of `cpu_adapter`, the selected Musashi core/generated code and an injected bus; the supplied `test_bus` belongs to the private harness. Unity, host generation, Python audit/evidence, and threads remain outside runtime linkage. CMake introduces `GLUEYNEO_CPU_EXPERIMENT` (default OFF), `GLUEYNEO_CPU_SANITIZER` (NONE, ADDRESS_UNDEFINED, THREAD; default NONE), and `GLUEYNEO_CPU_OPTIMIZATION` (NONE, RELEASE; default NONE), each validated and consumed by target-scoped options. Both runtime and test executables must be instrumented in sanitizer configurations.

Private names introduced: opaque `cpu_instance`; `cpu_create`, `cpu_destroy`, `cpu_reset`, `cpu_run`, `cpu_set_irq`; `cpu_run_result` containing requested/elapsed cycles, completed instructions, overshoot, stop/fault reason; `cpu_status` including invalid argument, allocation failure, unsupported model, stopped, budget and terminal host fault; per-instance allocator callbacks; `test_bus` with borrowed bounded buffers, userdata and bounded trace. Private `cpu_capture`/`cpu_restore` and `cpu_guest_state` arrive in plan 03. Define the declarations here only for implemented functions. Model selection admits only 68000. Single-thread access to each instance is required; independent instances may execute concurrently.

CTest names created here: `cpu_guest`, `cpu_guest_negative`, `cpu_closure`, `cpu_budget`, `cpu_audit_controls`. Labels `cpu` and `cpu-fast` are nonempty; CPU tests have finite loops and explicit timeouts (initially 30 seconds per fast test). Audit subcommands are `budget`, `closure`, `regenerate`, and `self-test`; they return nonzero on incomplete evidence. Generated artifacts stay at the two listed Musashi output paths; host tool scratch/results live under ignored build directories.
