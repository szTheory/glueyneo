<objective>
Gap 5 of 04-VERIFICATION.md: make the pinned RetroArch launch safe on a shared host (T-04-47; review findings CR-07, WR-03, WR-04, WR-05; validation escalation E6; the project rule of at most one RetroArch instance).

Today the smoke starts RetroArch in its own session. The runner's `subprocess.run(timeout=180)` kills only the smoke process, so its `finally` quit never runs and RetroArch is orphaned. Nothing checks for an existing instance before launch, and both the key injection and the bundle-id quit act on any instance. This plan adds a pre-launch refusal, PID-scoped quitting, signal-driven cleanup, process-group timeouts in the runner, and lane-level before/after instance assertions. It also hardens capture and decode so that failures stay inside the smoke's scanned JSON result.

The D4-02 controls (no-input stability, the Left Arrow wrong-input control, Right Arrow movement) and the D4-01 ordinary content path are unchanged.

Purpose: the 04-31 re-qualification and every later frontend run must not stack or orphan instances.
Output: hardened smoke and runner lifecycle, regressions that need no GUI, and the documented behavior.
</objective>
