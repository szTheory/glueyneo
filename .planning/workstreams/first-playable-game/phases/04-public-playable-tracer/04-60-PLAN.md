Decisions:
- **Generator scope (orchestrator resolution, 2026-10-11).** `main` is the single commit 2e5d884, so every phase of this milestone was built on this branch. The generator computes M = `git merge-base <head> <base>` (base default `main`, overridable with `--base` for clones without a local `main`) and enumerates every row the three gates check: the 04-REVIEW.md `reviewed_revision`; every revision cited in a recognized form by every non-open 04-REVIEW-DISPOSITION.md row (as written); the receipt `source_revision` when the receipt exists; every non-third_party rights item. It lists a row only when its revision is NOT an ancestor of M, with the 04-59 per-record pin. Rows reachable from main stay strict.
- **Strict pre-check.** Generation runs the three gates with `HistoryAllowlist.EMPTY` and refuses on any error or note. Only rows that verified strictly on full history can be listed, and generation is impossible on a squashed history (where listed rows are absent).
- **Freshness and the pre-ship step.** `check` compares the tracked file with what `write` would produce. Because pins are per record, the next `/gsd-code-review` appending rows voids nothing, while editing or adding cited rows makes `check` report stale; the pre-ship step regenerates (listing only strictly passing rows) and re-runs the squash simulation. After the milestone squash merge, `write` refuses (listed rows are absent), so post-ship rows are never covered.
- **Suite arbiter (orchestrator resolution).** No executor-written list is trusted, and a main-checkout pass proves nothing (every history-dependent failure passes there). SUITE-CHECK accepts a clone-only failure only after verifying each stated ignored input itself and demonstrating causation: a fresh copy of the squashed clone with only those inputs added passes the named test. Provisioning ignored inputs into the clone is preferred. Environmental entries must be repository-relative paths under `build/`, each with a recorded provisioning command in `04-59-squash-provision.txt`; the residual (history-dependent yet satisfied by an ignored `build/` input) is not mechanically detectable, so the executor-authored label is reviewed by the diff-scoped /gsd-code-review. The same SUITE-CHECK runs everywhere it is used (04-60, 04-61, 04-62).
- **Bounded scope (orchestrator resolution).** The first simulation's clone-only failures are recorded and classified before any repair; more than 5 history-dependent failures halt with `scope-split-needed: <n>` and route to `/gsd-plan-phase 04 --gaps --ws first-playable-game`.
- **History-absent rule in the simulation.** History-absent rule: a cited revision is history-absent when it does not resolve, or when it resolves but is neither an ancestor nor a descendant of the checked head (unrelated history, for example a squashed-away feature branch whose objects a local clone still holds). Ancestor and descendant revisions are always strict, and unlisted rows are strict in every case.
