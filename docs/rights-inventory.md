# Release rights inventory

This inventory applies to public source and release archives. An affirmative row
records the project's basis for distribution; scanner findings do not determine
whether that basis is legally sufficient. Every listed path is bound to its
current SHA-256 digest and must retain the named notice. Unknown items are
excluded from release inputs and block the gate.

The Unity source is the four-file subset copied from upstream commit
`b6763fbd9cedfacaa89e2ad9fd00d615a234e355`. Its upstream MIT license is retained
in `third_party/unity/LICENSE.txt`. Diagnostic and public playable fixture
recipes, manifests, guest source, generated sound assets, installed C sound
consumer and assertion contracts are original Glueyneo work under the repository
MIT license. The sound recipe and immutable source/asset identities are recorded
in `tests/fixture/rights-manifest.json`; its original BIOS-role launch substitute
is not SNK firmware. The generated67108976-byte GNMV sound artifact stays ignored
and is reproducible from the audited C generator. Its SSG/ADPCM-B program and
sample formula contain no game, commercial BIOS, private capture or imported
guest bytes. The private C interface does not transfer ymfm authorship: its
pinned third-party BSD notice and source provenance remain separate. The experimental
Musashi tree is excluded from the SDK source archive because the candidate was
not admitted. Its permissively licensed experimental source and notices remain
in repository history; `third_party/musashi/PROVENANCE.md` and
`tools/cpu/source-manifest.json` record the immutable origin, adapted/generated
bytes and retained grants. Repository publication preserves those notices.
This does not admit that candidate into the SDK runtime.

`source_revision` has one definition. For `third_party/` rows it is the upstream
commit the bytes were copied from. For every other row, `path` is a
relative POSIX path (non-empty, not starting with `/`) with
no `..` segment and no leading `-`, and `source_revision` is a commit of this
repository, written as 40 lowercase hex, that resolves, is an
ancestor of the checked head, and whose blob at `path` has exactly the
recorded sha256. Those five parts (path form, 40 lowercase hex, resolves,
ancestor of the checked head, digest equals the recorded sha256) are the whole
definition for every row whose revision is an ancestor or descendant of the
checked head and for every row not listed in `docs/history-allowlist.json`, and
are exactly what `tools/verify_playable.py --check-docs` and the
`qualification_runner` CTest check for those rows.
History-absent rule: a cited revision is history-absent when it does not resolve, or when it resolves but is neither an ancestor nor a descendant of the checked head (unrelated history, for example a squashed-away feature branch whose objects a local clone still holds). Ancestor and descendant revisions are always strict, and unlisted rows are strict in every case. A local squashed repository that still holds the branch objects and a fresh clone without them behave identically: both tolerate an allowlisted, pin-matching row, and both are strict for an unlisted row. A listed pre-ship row of the first-playable-game milestone branch (cited revision not reachable from `git merge-base HEAD main`) whose revision is history-absent (as after a squash merge, in a fresh clone or in a local clone still holding the branch objects) is instead accepted, permanently, when the committed file at the checked head hashes to the recorded sha256 and the row's own pin (the canonical digest of this item) matches, and is reported as `unverifiable-history`; editing the item voids that pin until the pre-ship `--history-allowlist write` runs; see docs/testing.md "History gates after a squash merge". By convention
the refresh procedure writes the last commit that changed the file; that is a
convention, not part of the definition, and the gate does not check it.

The nested first-party source identities in `tests/fixture/rights-manifest.json`
are additionally checked against their cited source commits and blobs on full
history. If squash removes those commit objects, the exact canonical pin of the
manifest's affirmative outer rights row plus the checked-head path, byte count,
and SHA-256 are still required; the gate reports unavailable ancestry as
`unverifiable-history`. That fallback proves current bytes under the pinned
manifest, not the historical source commit's contents. A full-history
public-content check is required before merge, and available non-ancestor
revisions or mismatching blobs still fail.
